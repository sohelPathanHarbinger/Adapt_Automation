# Template reference

Two documents, and a course that builds.

It lives in `Documentation/` rather than `Inputs/` because it is reference
material that ships with the repo, while `Inputs/` holds live client courses and
is not committed. `build.py` takes a path, so it still builds from here.

| File | What it is |
| --- | --- |
| `Template Reference Storyboard.docx` | a complete, minimal storyboard that exercises **every** component the automation can build |
| `guide/Storyboard Authoring Guide.docx` | the conventions: which Word style becomes what, and how to ask for each component |

Both are generated with the real Word styles the parser reads, so the guide is
not a description of the conventions — the storyboard next to it is a working
example of them.

## Build it

```bash
python build.py "Documentation/Template_Reference"
```

It produces a course containing one of every supported component. That makes it
the regression test for the automation: change the parser, rebuild this, and
check the report.

Three warnings are expected and are the point of the exercise:

- **no print PDF** — this folder has no `.pdf`, by design;
- **hotgraphic pins are placeholders** — `base/Source` has no matching
  hotgraphic to inherit positions from;
- **`selectchoice` plugin missing** — see below.

## Why the guide is in a subfolder

The builder reads the newest `.docx` at the top level of a course folder. Two
documents side by side would make which one is the storyboard depend on which
was saved last, so the guide sits in `guide/`, where the builder ignores it.

## A finding worth knowing

`base/Source` does not have the `adapt-selectchoice` plugin installed, but the
automation generates `selectchoice` components for the grid questions in
NBIX 1513 M4. A course built from `base/Source` will not render them. Either
install `adapt-selectchoice` into `base/Source` — it is present in
`Inputs/NBIX 1513 M4 Ingrezza/ingrezza_..._source_11062026/src/components/` —
or those questions need authoring another way. Every build now checks this and
warns.

## Regenerating these files

They were generated by a script rather than authored by hand, so the styles are
guaranteed to match what the parser expects. To change them, edit the storyboard
in Word directly — or, for a structural change, regenerate from the script that
produced them and keep this folder in step.
